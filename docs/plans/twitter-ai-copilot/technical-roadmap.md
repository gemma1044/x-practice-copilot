# X Practice Copilot｜从 Demo 到可用扩展的技术里程碑

## 目标与可用定义

目标是交付一个可在 Chrome / Edge 本地加载的 Manifest V3 扩展：用户在 X 单帖内进入唯一侧栏，能够获得 AI 评论、把帖子转成可实践的灵感，并将当前公开视频下载到本机、截取代表帧后生成视频拆解与 Medeo prompt。扩展不自动发帖，不在包内保存模型密钥。

“可用”同时满足：真实 X 页面可稳定触发、真实 AI 链路可完成、数据不会因刷新丢失、失败可恢复、隐私边界清楚，并通过一次端到端人工验收。

## 里程碑

| 里程碑 | 交付物 | 验收门 | 依赖 |
|---|---|---|---|
| M0 基线锁定 | 现有 MV3 壳、Demo、connector/repository/evidence 抽象与自动测试形成基线；解决“个人飞书是否已确认”的文档冲突 | `npm test` 全绿；唯一入口和唯一数据通道有记录；明确 Git 是否初始化 | 无 |
| M1 浏览器真机壳 | 在 Chrome / Edge 加载未打包扩展；完成 X 动态信息流注入、单帖上下文捕获、侧栏切换与重复注入防护 | 连续检查 10 条帖子，三个入口均指向正确帖子；刷新、站内跳转后仍工作；不触发发帖 | M0 |
| M2 真实文字 AI | 新增本机 loopback bridge；密钥只读本机环境；接通 Merouter 文字模型；评论与灵感复用同一连接器；补齐超时、结构校验和错误态 | 一条真实帖子可生成 3 条可编辑评论；灵感最多问 2 题，第二题直接给具体脚本 idea；断网或超时时不丢上下文 | M1、Merouter 凭据 |
| M3 灵感到实践闭环 | 落实主张审计、证据补充、实践状态推进和草稿回填；AI 建议与用户事实分栏保存 | 无证据时不生成“我已实践”的事实；补入证据后可形成可追溯草稿；AI 不自动推进状态 | M2 |
| M4 个人数据持久化 | 在确认个人飞书身份和 Base 后实现远程 repository；提供本地队列、upsert、回读和同步失败重试 | 灵感、实践、证据与来源链接可回读；重复保存不重复建记录；公司租户零写入 | M3、个人飞书确认 |
| M5 本机视频 MVP | 当前公开视频经 bridge 串行下载到临时目录，FFmpeg 识别场景并为每场景截取 3 帧，每 3 个场景合成一张九宫格；用户确认后由 Merouter `gemini-3.7-flash` 输出完整 Medeo prompt | 默认无 Cookie、无批量；限制时长和大小；429/403 停止重试；原视频和单帧及时清理；至少 1 张九宫格才可分析 | M1、yt-dlp、FFmpeg、Merouter 凭据 |
| M6 可用发布候选 | 选择器降级策略、权限最小化、数据版本迁移、错误与离线状态、安装说明、隐私说明、Chrome / Edge 回归清单 | 三条主流程各通过一次端到端验收；扩展包中无密钥；升级不破坏本地数据；已知限制写清 | M2–M5 |

- **M0 已通过**：Git 已初始化；个人飞书文档冲突已按保守口径统一为“候选配置尚未核验”；唯一入口和数据通道路标已记录；`npm test` 全绿。
- **M1 自动验收已通过**：Playwright 在真实 MV3 Chromium 运行时加载未打包扩展，以本地十帖夹具验证 30 个入口、三种正确上下文、侧栏打开响应、重复注入、站内换页、刷新和误触防护。

- **M2 本地实现已完成，真实验收待凭据**：loopback bridge、唯一文字 connector、来源/大小/超时/结构校验及错误态均通过 mock 测试；没有真实 Merouter 成功证据。
- **M3 本地闭环已通过**：灵感、实践、用户确认的证据和事实草稿主张映射可保存、刷新回读；AI 建议不能自动成为证据或推进状态。
- **M4 基础能力已完成，远程适配器阻塞**：同一版本化状态已具备迁移、upsert、回读、去重队列和失败重试；个人飞书身份、权限及表结构未核验，因此没有远程读写。

- **当前剩余外部验收项**：个人飞书确认、Medeo 生成和 Edge/真实 X 发布回归仍需对应环境。

## 分段可见成果

- **文字 Alpha（M1–M2）**：最早可看到真实 AI 工作，先验证核心价值。
- **本地 MVP（M1–M5）**：评论、灵感实践、本机视频拆解三条主流程闭环。
- **可用候选（M6）**：适合小范围日常使用；Chrome Web Store 上架不在本轮范围。

## 技术主线与约束

1. 浏览器侧只负责页面上下文、交互和本地缓存；所有密钥与外部模型调用放在本机 bridge。
2. 评论和灵感只保留一个 `TextGenerationConnector`；视频准备只经同一本机 bridge，代表帧分析只保留一个 `VisionAnalysisConnector`；业务数据只经 `PracticeRepository`。
3. 先让 Chrome Storage 完成闭环，再以相同 repository 接口接个人飞书；未确认个人身份前不做远程写入。
4. 每个里程碑先做现实核对，再实现，再由独立验收清单收口；同一问题返工两次时才升级为更重的循环评审。

## 管家机制

建议启用独立项目管家。管家只维护基线、依赖、验收证据和下一里程碑，不复制实现、不创建第二入口或第二数据通道。

管家每轮只做四件事：

1. 核对代码、文档、测试与浏览器现状，更新里程碑状态。
2. 为当前里程碑给出一个可执行任务和明确验收门。
3. 记录外部依赖与用户决策，不把未确认事项写成已完成事实。
4. 验收通过后再推进下一里程碑，并同步 `CHANGELOG.md`。

当前下一步按依赖解锁顺序执行：个人飞书只读核验后再启用同步 → Medeo 真实生成回收 → Chrome / Edge 真实 X 发布回归。任何一项未提供外部条件时保持阻塞，不以 mock 代替真实验收。
